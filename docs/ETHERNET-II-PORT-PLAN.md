# Ethernet II controller port - plan

Port of the RetroCore ND-100 Ethernet II card (PCB 3094) to nd100x, with the
on-card 68000 run by Musashi (`external/Musashi`) instead of RetroCore's
`Cpu68K`. Branch: `eth-impl`.

Paths to RetroCore files are written relative to `$RETROCORE_DIR` (the root of
the RetroCore checkout). Paths to nd100x files are relative to the repo root.

Status: PLAN ONLY. Nothing below is implemented. Decisions are in section 2.

---

## 0. Ground rules for the port (apply to every phase)

These exist because an AI doing a large port reliably skips things, stubs
things, "simplifies" things and then reports them as done. Every rule below
turns a claim into something a script or a test can check.

R1. **Nothing is "done" on a claim.** A todo is done only when its listed
    check passes, and the check output is pasted into the phase log
    (`docs/ethernet-port/PHASE-LOG.md`).
R2. **Every source member is accounted for.** The traceability matrix
    (Phase 1) lists every C# type, method, field, constant, enum value and
    `case` label in the ported files. It is generated by a script, not typed
    by the AI, so rows cannot be left out. Every row maps to a C symbol with
    file:line, or to `NOT PORTED` with a reason Ronny has approved.
R3. **No silent stubs.** A script fails the build check if ported files
    contain: `TODO`, `FIXME`, `stub`, `not implemented`, `XXX`, an empty
    function body, or a function whose whole body is `return 0;` /
    `return;` / `return false;` unless the matrix row says that is what the
    C# does (with the C# line).
R4. **Constants are copied, not retyped.** Every numeric constant (register
    offsets, bit masks, vectors, addresses, IDENT codes, delays) is checked by
    a script that extracts it from the C# and from the C and compares the
    values.
R5. **Tests are ported one-for-one.** Every RetroCore test in scope gets a C
    test with the same name and the same asserted values. A script compares
    the two name lists; a missing or renamed test fails the check. A ported
    test may not weaken an assertion (fewer asserts, wider tolerance,
    `skip`) without a matrix row Ronny approved.
R6. **Behaviour is compared against the RetroCore card, not against the
    AI's reading of it.** Differential traces (Phase 2 and later): the same
    stimulus is run through the C# card and the C card, both emit the same
    trace format, and a script diffs them. "Matches" means the diff is empty.
R7. **Coverage is measured.** gcov/lcov per ported file. Any line not
    covered by a test is listed in the phase log with a reason.
R8. **Mutation spot check.** At the end of each phase a script flips
    a sample of constants and comparisons in the ported C (one at a time)
    and runs the tests. Every mutant must make at least one test fail; a
    surviving mutant means a test is missing.
R9. **Independent review.** At the end of each phase a separate agent
    session, given only the C# file, the C file and the matrix (not the
    porting session's notes), checks a random 10 % of matrix rows line by
    line and reports mismatches. Ronny spot-checks rows of his own choice.
R10. **Unknowns stay unknown.** Anything the C# does that is not
    understood is ported as the C# does it and marked in the matrix as
    "behaviour copied, meaning unverified". It is never "fixed" or
    "simplified" during the port.
R11. **No edits to RetroCore or Musashi** unless Ronny approves the specific
    change (needed for the trace hook in Phase 0, see DECISION D3).
R12. House C standard (`c-coding-standard`, nd100x profile) for every new
    C file. Musashi and `src/devices/ethernet/m68k/generated/` are exempt.

## 2. Decisions (answered by Ronny 09-OCT-2026 unless marked open)

- **D1** Port the 68000 card only (`NDBusEthernetII.cs` + chips, run by
  Musashi). The HLE card (`NDBusEthernetIIHle.cs`) is not ported.
- **D2** Firmware images are copied into the repo (planned folder
  `images/ethernet/`): `pioc-ether-68k-code.srec/.bin`,
  `TCP-SER-B0-D02.BIN`, ENCOS-SER-B0..B3-B01:BPUN. Tests always run.
- **D3** Yes: a small opt-in trace emitter is added to the RetroCore card
  and its chips (off by default), so R6 differential traces are possible.
- **D4** Backends in this order: UDP + TCP (+ listen), then pcap (libpcap /
  Npcap loaded at run time), then TAP on Linux. Plus WASM, see D7.
- **D5** Clock model = RetroCore's, measured from its source (phase log
  2.5): one 68000 instruction per ND-100 tick, NOP 4 ticks, interrupts
  checked before the instruction.
- **Bus error** (09-OCT-2026): Musashi replaced by the fork
  https://github.com/RetroCoreLabs/Musashi, patched to push the 68000
  7-word bus error frame (fork commit 328a672).
- **D6** One card in the first version (thumbwheel 0). Musashi's CPU state
  is a single global (`external/Musashi/m68kcpu.c:81`), so more cards need a
  context copy per switch (`m68kcpu.c:1172-1180`) and a "current card"
  pointer for the global memory callbacks. The glue is written so both can
  be added later without restructuring. `Nd100MultiEthernetConfigTests`
  become approved NOT PORTED rows for now.
- **D7** Ethernet is ON for WASM. Frames go over the existing WebSocket
  gateway; the gateway is extended, or reuses the NDIX ethernet frame
  support if one exists (not yet checked - todo 6.7).
- **D8** CLI `--eth0=<backend spec>`, INI `[controller.eth.0]` with key
  `net = <backend spec>`, CLI wins. Specs: `udp[:group:port]`,
  `tcp:host:port`, `listen:port`, `pcap:<iface>`, `tap:<if>`, `ws` (WASM).

## Phase 3 - Clean-room 68000 interrupt glue

Musashi provides the CPU-side behaviour (IPL as a level, level-7 transition
NMI, mask compare, IACK callback with vectored/autovector/spurious, RESET
callback). The card-side logic is written new in C from the behaviour list
below, each item from the RetroCore analysis with its source line. Every item
is one test, written before the code.

Behaviour list (each becomes a test; the test name carries the item id):
- I1 Level mask of pending sources; highest set level drives
  `m68k_set_irq` (card priority encoder, E2:209-221, 3289-3334).
- I2 Master gate: no interrupt delivered while the card is halted or in
  reset (INT:168-191, 312; E2:1866-1874). Musashi has no gate - glue
  withholds the IPL.
- I3 Source wiring: L7 power-low (unmodelled - confirm with matrix row),
  L6 OPCOM (control bit 3), L5 MERR + STC timer, L4 console, L3 MFP, L2
  LANCE INTR held level.
- I4 IACK L2: autovector; re-assert L2 if LANCE still holds INTR
  (E2:838-880).
- I5 IACK L3: vector from the MFP; 0 means spurious (E2:783-807).
- I6 IACK L5/L6: autovector, clear timer-pending flag, deassert
  (E2:742-958).
- I7 IACK L7: autovector, deassert. Other levels: spurious.
- I8 Pending bit cleared before the IACK callback (INT:340) - compare with
  Musashi's order and record the difference if any.
- I9 STOP wake-up: pending level above mask clears STOP, then the
  interrupt is taken (INT:316-329) - test against Musashi.
- I10 Vector 15: RetroCore substitutes vector 15 when the vector table
  entry is 0 (Instructionset.Helpers.cs:1502-1512). This is RetroCore
  behaviour, not documented 68000 behaviour. **DECISION** for Ronny:
  copy RetroCore's behaviour or follow Musashi.
- I11 External reset loads SSP/PC from vectors 0/1; PC == 0 keeps the CPU
  stopped (Cpu68K.cs:845-851).
- I12 RESET instruction does not reset card peripherals (E2:670-675).
- I13 Interrupts sampled only at instruction boundaries
  (Cpu68K.cs:520-526) - check Musashi matches.
- I14 Runaway guard after 100 consecutive traps, double fault = crash
  (Cpu68K.cs:553-578) - port or not is a matrix row for Ronny.

## Phase 6 - Host networking (send/receive real ethernet frames)

Background facts (RetroCore, from the analysis): backend interface
`IEthernetBackend` (Start/Stop/SendPacket/OnPacketReceived), specs
`pcap:<iface>`, `udp[:group:port]` (default 239.3.9.4:3094),
`tcp:host:port`, `listen:port`. Card glue: drop own echoed frames by source
MAC, repair offloaded IP checksums, pad runts to 60 bytes
(E2:1994-2068).

Options for real frames on the host (facts to be verified in 6.1 before a
choice):
| Backend | Linux / ARM Linux | Windows | Needs | Notes |
|---|---|---|---|---|
| pcap | libpcap | Npcap | root or CAP_NET_RAW (Linux), Npcap driver (Windows) | Puts the emulated card on the real LAN with its own MAC; host-to-guest traffic on the same NIC may not loop back (unverified) |
| TAP | `/dev/net/tun` IFF_TAP | TAP-Windows6 driver (OpenVPN) | root/CAP_NET_ADMIN to create; bridge for LAN access | Host can talk to the guest directly; Wintun is layer 3 only (unverified, check) so not usable for ethernet frames |
| UDP multicast hub | sockets | sockets | nothing | Compatible with RetroCore's `udp` backend, so nd100x and RetroCore cards can talk to each other - useful as a cross-check (R6) |
| TCP point-to-point | sockets | sockets | nothing | u16 big-endian length framing, same as RetroCore |

Suggested order (DECISION D4): UDP + TCP first (portable, no privileges, and
can talk to a running RetroCore card for interop testing), then pcap
(Linux libpcap + Windows Npcap loaded at run time so the binary still runs
without Npcap installed), then TAP on Linux. RISC-V: none by
default. WASM: `ws` through the gateway (D7).
